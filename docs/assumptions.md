# Assumptions made during scaffolding

Each assumption is numbered so it can be referenced from ADRs, the plan and PRs. Revisit when the
first vertical slice (M1) lands; anything proven wrong becomes an ADR amendment.

| # | Assumption | Rationale / consequence |
|---|---|---|
| A-01 | Python 3.12 is the target runtime for `services/media-worker`; CI also validates on 3.11. | AWS Batch / ECS images will pin 3.12. 3.11 in CI keeps us honest about not using 3.12-only syntax until every image is upgraded. |
| A-02 | All 22 seed locale codes are seeded as `beta`; no target is `production`. | No benchmark has run. Promotion happens only via `quality-benchmark.md` rules. |
| A-03 | The existing pipeline (stacks `PodcastLanguageEncoder`, `PodcastLanguageEncoderGithubOidc`) remains under `infra/` as the "legacy encoder" and keeps working until Polycast replaces it. | Avoids breaking the only thing that currently deploys. Polycast stacks get a `Polycast*` prefix. |
| A-04 | Dev deploys go to AWS account 559315537226, us-east-1, using the existing GitHub OIDC role. | Role policy may need widening for new services (ECS, Aurora, Cognito, EventBridge); tracked in M2. |
| A-05 | Web hosting: CloudFront + S3 for static assets, Next.js standalone server on ECS Fargate for SSR/route handlers (ADR-0001). Amplify Hosting was considered and rejected. | Keeps the web tier in the same VPC/ALB as the API, allows SSE proxying without Amplify's timeouts, one deploy mechanism (CDK). Revisit if ops burden is high. |
| A-06 | API framework is Fastify with Zod type providers and generated OpenAPI under `/api/v1` (ADR-0002). | Fast, schema-first, SSE-friendly. NestJS rejected for weight; tRPC rejected because Python workers and external clients need OpenAPI. |
| A-07 | Tests: Vitest for all TypeScript packages and apps; Jest stays in `infra/` for the legacy CDK assertions. | Migrating `infra/` tests brings no value now. Turborepo runs both. |
| A-08 | Local orchestrator adapter (`packages/domain` orchestration port, implemented in `apps/api`) mirrors Step Functions stage semantics: same stage names, same input/output shapes, same retry/catch behaviour. | M1 runs end to end without AWS. Step Functions definitions in M2 must be generated from the same stage table to avoid drift. |
| A-09 | MinIO stands in for S3 locally, including multipart upload and presigned URLs. | Bucket names and key layout identical to AWS. Event notifications differ; the local adapter polls or is called directly by the upload-complete endpoint. |
| A-10 | Postgres 16 via docker compose locally; Aurora PostgreSQL Serverless v2 in AWS (ADR-0003). | Same SQL, same migrations. RLS policies tested locally. |
| A-11 | No Redis in v1. | SSE fan-out is per API instance backed by Postgres LISTEN/NOTIFY; rate limiting uses Postgres counters. Introduce Redis/ElastiCache only if an observed bottleneck demands it. |
| A-12 | Media time is integer microseconds (`int64`) everywhere: DB, contracts, Python. Never floats, never milliseconds. | Avoids drift across ffmpeg, providers and captions. Helpers live in `packages/domain/src/time/media-time.ts` and `polycast_worker/mediatime.py`. |
| A-13 | All IDs are UUIDv7. | Time-ordered for index locality; generated by the API, never by the DB. |
| A-14 | Auth is Cognito in AWS; locally a Cognito-compatible JWT mock issues tokens with the same claims (`sub`, `org_ids`, `role`). | UI and API code paths are identical in both environments. |
| A-15 | Polycast CDK stacks synthesize in CI but are deployed only through the manual `deploy-polycast` workflow (owner's decision); the legacy encoder keeps deploying on push to `main`. | Documentation describes target state; the traceability table marks status. |
| A-16 | Provider adapters are Protocols in `polycast_worker/providers/base.py` (transcription, translation, speech, lip sync, encode, quality) with `CapabilityRecord` mirrored by `packages/domain/src/capabilities/registry.ts`; only `Mock*` implementations (`providers/mock.py`) exist. | The capability registry is what makes a locale selectable. `Mock*` adapters register as tier `unavailable`; the seed locales carry `beta` in the registry as the intended tier once a real adapter exists, and the M1 local slice runs the mocks through an explicit dev-only override, never by promoting them. |
| A-17 | Transcripts, media, signed URLs and biometric data (face embeddings, voice embeddings) are never logged; loggers redact by key allowlist. | Enforced by a lint rule and a logging test that fails on forbidden keys. |
| A-18 | Single region (us-east-1) for v1; the `region` field on Organization exists but only one value is accepted. | Residency (NFR-004) is satisfied trivially; multi-region is a later ADR. |
| A-19 | pnpm 9 and Turborepo 2; Node 20 LTS. | Matches AWS Lambda/ECS Node 20 images. |
| A-20 | Lip-sync inference runs on AWS Batch with GPU instances, not SageMaker endpoints, in v1. | Batch fits bursty, long-running per-shot jobs and is cheaper at low utilization. Decision recorded in ADR-0005 and revisited in M4. |
